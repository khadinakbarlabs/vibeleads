# A seller has introduced themselves

In a VibeLeads conversation, “I am a video editor” means the seller wants buyers of editing. An employer hiring an editor wants candidates. An explicit request to hire, enrich an existing list or target a particular ICP takes precedence. “Find me editors” by itself merits one question about hiring versus finding clients. If the conversation has another purpose, a profession alone is insufficient reason to start prospecting.

1. Extract the paid outcome, buyer, role, geography, exclusions, signals, requested contacts, quantity and spending decision from the conversation. Keep all explicit requirements. Treat inferred segments as hypotheses. For an unfamiliar but understandable profession, reason from who pays for the deliverable and what observable event creates need. For an opaque title like XYZ, ask only what customers pay them to deliver. If geography is missing, start a location-independent route while a local plan awaits a market. Don't assume the seller's language establishes a country.
2. Use the bundled [method map](seller-methods.json) to compare genuine commissioned work, activity suggesting fit, and cold target accounts. Use the matching profile's methods or compose the general methods for a different trade. The optional local helper `scripts/seller_plan.py`, relative to this skill, renders the map offline. Pass the quoted brief as one safely encoded argument; use `--answers` with one JSON object for known fields such as offer, serviceTerm, segment, role, market, country (ISO 2), language, constraints or intent. When local execution is unavailable, read the map directly. Never execute user text as shell code.
3. Choose and run the first feasible discovery step; do not ask the seller to choose websites or gather URLs. If included public web search is available, run a buyer-language query generated from the seller's service, find originals, and show the attributable links and dates. Use only permitted, readable public sources within the user's restrictions. Separate these host-reviewed results from Actor-saved lists. If search is unavailable, restricted or empty, advance to the next callable Actor method. One tutorial's example account is never a search seed. Use any already stated place; ask one optional service-area question only if it would materially improve the next lead source.
4. For Actor methods, fill all mandatory fields with supported values, use the exact returned quote/next-call, show costs (including unknown usage), retain the seller's quantity/cap, and execute only after approval covers that work. The map's sample count is for a quote, not permission or a replacement for a stated count. Keep geographic, role, channel, exclusion and evidence filters even on fallback. If nothing satisfies a hard filter, report the specific gap. Save local results using the returned list ID, then read/export using get_leads or export_leads. For B2B use lead_search_status with listId, offset and limit. Channel searches may return a run/dataset rather than a list; retain its actual reference. Never call an unreleased name or say a host original was saved to Apify without a receipt.
5. Report open buyer requests first; next show good fits without an active request. Separate sellers offering the same service, closed requests and unrelated activity. Show why each actual candidate fits, source link, original date if known, permitted reply/booking route or separately sourced business contact, and uncertainty. If no buyer can be substantiated, say so and try an eligible alternative within the existing budget. Finish at a useful discovery result or a concrete price/permission decision.

### Offers beyond the examples

The host assistant supplies the reasoning. For every understandable offer missing from the map, infer **two concrete buying organizations** and one relevant role from the paid outcome. For example, a technical manual translator could approach equipment exporters or device manufacturers. A supplier of reusable containers could approach meal-prep companies or commercial caterers. Call the helper with the most relevant serviceTerm, segments array, role and saleType (service, product or software), then run the first feasible method. If the helper returns assistantInference, complete it yourself and render again. The seller should only have to explain an opaque title or a choice that changes what can actually run.

Pass explicit segment, market, country, count and allowedMethods where the conversation specifies them. Keep role, hard exclusions, required demand, contact proof and spend separately for qualification. Use only the buyer category and market in company discovery; use only the actual vacancy title in job search. For an existing vertical software product or wholesale item use its actual category in buyer-request queries. A recommendation request is a separate signal from a purchase order. Before following the returned paid plan, compare its effective inputs, geography, count and quote against the original brief.

A named exclusive source is a hard limit across every fallback. When YouTube alone is allowed and the seller supplies country and language, use those values for the channel plan. Without a region, try an included search scoped to youtube.com for the seller’s channel topic. If the host cannot search, ask which missing market or language to use. Skipping one social platform leaves other permitted originals available. For country or language names outside the helper’s shorthand, pass the explicit ISO codes from the brief.
